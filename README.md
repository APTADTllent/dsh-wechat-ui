# dsh-wechat-ui

> 把 DSH（DeepSeek Harness）的聊天界面换成**微信风格** ·
> A WeChat-style chat UI plugin for DSH.
>
> 气泡换肤、思考过程折叠、表情包与图片头像、桌面确认窗口、自动推进器、
> 定时截屏与「让 AI 看屏幕」。

只接管 `user` / `assistant-step` 两个渲染节点，**其余全部回落官方渲染器** ——
所以官方界面更新时，这个插件不会把整个聊天页搞坏。

---

## 安装

### 一条命令（推荐）

```bash
dsh plugin add https://github.com/APTADTllent/dsh-wechat-ui.git
```

DSH 会把这个仓库拉进 profile 的 `node_modules` 并注册好。

### 手动安装（备用）

如果上面那条命令不可用，手动来：

**1. 放进 DSH profile 的 `node_modules`**

把本目录整个复制过去：

```
<DSH_HOME>/profiles/web/node_modules/dsh-wechat-ui
```

`<DSH_HOME>` 通常是 `~/.dsh`（Windows 上是 `C:\Users\<你>\.dsh`）。
复制完确认 `<DSH_HOME>/profiles/web/node_modules/dsh-wechat-ui/package.json` 存在。

**2. 在补丁文件里注册**

编辑 `<DSH_HOME>/profiles/web/cordis.patch.yml`，加一段：

```yaml
- insert:
    - id: wechat-ui
      name: 'dsh-wechat-ui'
```

**3. 重启 DSH**

改完补丁必须重启。重启后页面右下角应该出现 `😊`（表情）和 `⚙`（设置）两个浮动按钮。

### 设置表情包目录（建议）

插件会从一个目录里读表情图片。显式指定：

```
DSH_WECHAT_STICKERS=D:\你的\表情包目录
```

目录里放 `jpg` / `png` / `gif` 等图片即可。不设也能跑，只是表情面板会是空的。

### 怎么确认宿主半加载了

请求 `<你的 DSH 地址>/wechat-ui/stickers`：

| 返回 | 含义 |
|---|---|
| JSON（表情列表） | ✅ 宿主半已加载 |
| **404** | ❌ 没加载 —— 重启 DSH |
| **401** | ✅ 加载了但要鉴权（页面内同源 fetch 会自动带 cookie，正常） |

### ⚠️ 最容易踩的坑

补丁行里的 `name` 必须是**裸包名**，且该包要能被 Node **从本 profile 解析到** ——
即 `profiles/web/node_modules/dsh-wechat-ui/package.json` 必须真实存在。

**解析失败会被静默跳过**（`pkgMeta = null`），症状是「界面没变化」，
但**不报任何错**。装了却没反应，先查这里。

卸载就是删掉补丁里那几行，再重启。

### 桌面功能的系统要求

`scripts/` 下那六个脚本是 **Windows PowerShell**。
插件主体（`lib/`）是纯 ESM JavaScript，但**桌面通知、桌面确认、截图、
热键框选这些功能依赖 Windows**。非 Windows 平台上界面部分仍可用。

## 关于进程调用与网络（安全评审说明）

这个插件会调用 `child_process.spawn` 启动**本仓库自带**的 PowerShell 脚本：

```js
spawn('powershell', ['-NoProfile', '-ExecutionPolicy Bypass', ...args])
```

### 为什么用 `-ExecutionPolicy Bypass`

`.ps1` 脚本在 Windows 默认执行策略（`Restricted`）下**根本无法执行**，
所以必须显式绕过。三点说明：

1. 它**只作用于这个子进程**，不会修改系统或用户的执行策略 ——
   没有 `Set-ExecutionPolicy`，不写注册表。
2. 脚本路径**固定在 `scripts/` 目录内**，由宿主半代码构造，
   **不接受来自模型或网络的路径拼接**。
3. 被调用的是哪六个脚本、各自做什么，全部列在上面「桌面工具」一节。

调用点共 4 处（`index.js` 第 731 / 831 / 977 / 1908 行）。

### 网络

这个插件**不发起任何外部网络请求**。唯一的 HTTP 服务是挂在 `/wechat-ui`
前缀下的**只读图片路由**（从你指定的表情包目录读图），
并带有双重防目录穿越校验（见下面「安全设计」）。

`scripts/desktop-say.ps1` 会请求 `http://127.0.0.1:<port>/wechat-ui/...`，
那是**本地回环地址**，用于自检宿主半是否存活。

**没有硬编码密钥，没有 `eval` / `new Function`，没有递归删除，没有任何遥测或数据外发。**

## 功能

| 功能 | 说明 |
|---|---|
| 微信气泡 | 你的消息右对齐绿气泡，AI 的左对齐白/深色气泡，带小尖角 |
| 折叠思考 | 思考过程收成一行「▸ 思考过程 · N 字」，点开才展开 |
| 过滤 NEXT | 你发纯 `NEXT` 时不再显示成气泡（「NEXT 之后做什么」这种正常句子不受影响） |
| 图片头像 | AI 头像从表情包里取，按回合轮换；你的头像也可以指定 |
| 自动发表情 | 按回复内容挑一张合适的贴图（关键词 → 情绪标签匹配） |
| 表情面板 | 点表情 → 往输入框插 `[表情:文件名]` → 发送后 AI 就用那张 |
| 设置面板 | 开关与滑块：浮动按钮、自动表情、发表情频率、头像轮换、轮换间隔 |
| 桌面通知 | 回复超过 20 字截为「前 11…后 8」，每条最多 3 个，停留 6s |
| 桌面确认 | 权限确认和提问弹成独立小窗，带浏览器心跳检测 |
| 自动推进器 | 自动发 `NEXT` 让对话继续跑，**带全套刹车**（空闲/对话中分别限流、连续上限、每日硬上限） |
| 定时截屏 | 每 N 秒截一张，保留固定张数 |
| 框选提问 | 热键 `Ctrl+Alt+Q`，框选屏幕区域直接提问 |

**发表情的闭环**：你点表情面板里的某张 → 它被插进输入框变成 `[表情:xxx.jpg]` →
你发出去 → 回复时前端认出这个标记，就用那一张。**不需要任何新通道。**

**浮动按钮**：右下角 `😊`（表情）和 `⚙`（设置）。不想看就在设置里关掉。

## 用法教程

装好并重启 DSH、刷新一次页面之后：

**1. 换气泡和折叠思考** —— 自动生效，不需要任何配置。

**2. 发表情** —— 点右下角 `😊`，选一张。它会被插进输入框变成 `[表情:xxx.jpg]`，
你发出去，AI 回复时就会用那一张。

**3. 改表情包目录** —— 设环境变量 `DSH_WECHAT_STICKERS` 指向你的图片目录，
重启 DSH。目录里放 `jpg` / `png` / `gif` 都行。

**4. 让 AI 看屏幕** —— 按 `Ctrl+Alt+Q`，框选屏幕上一块区域，松手就会把这块截图发给 AI。

**5. 调外观** —— 点右下角 `⚙`：开关浮动按钮、自动表情、发表情频率、
头像轮换、轮换间隔都在这里。

**6. 自动推进**（请谨慎） —— 设置里打开后，AI 回复完会自动发 `NEXT` 让它继续干活。
它带三重刹车（空闲 / 对话中分别限流、连续上限、每日硬上限），
但仍然建议只在盯着屏幕时用。

**7. 关掉桌面通知** —— 不需要的话在设置里关，或者直接不启动桌面工具脚本。

## 两半结构（改之前必须知道）

这个插件分**宿主半**和**浏览器半**：

| 文件 | 角色 | 改了怎么生效 |
|---|---|---|
| `lib/client.js` | 浏览器半：气泡、表情面板、设置界面 | **刷新页面** 即可 |
| `lib/index.js` | 宿主半：图片路由、桌面工具接线 | **必须重启 DSH** |
| `package.json` | 包元数据 | 必须重启 DSH |
| `assets/stickers.json` | 表情标签表 | 重启 DSH（宿主每次请求都重读，其实刷新页面也行） |

**为什么**：`cordis.patch.yml` 的 `patchReload: live` **只监视补丁文件本身**的变化。
你改了插件文件但没动补丁，DSH 就不知道要重新加载 —— 表现为新路由 404、新界面不出现。

## 桌面工具（`scripts/`）

宿主半会调用这些 PowerShell 脚本，实现「桌面」那一侧的能力：

| 脚本 | 作用 |
|---|---|

| `hotkey-watch.ps1` | 全局热键监听（`Ctrl+Alt+Q`） |

## 安全设计

这个插件有宿主半（要读你磁盘上的图片），所以做了这些：

1. **只读**：只暴露一个目录，没有任何写操作。
2. **双重防目录穿越**：文件名白名单（`[A-Za-z0-9._-]` + 图片扩展名）
   ＋ 解析后绝对路径前缀二次确认。已测 10 种攻击向量
   （`../`、`..%2F`、反斜杠、绝对路径、空字节截断、双重点点…）**全部 404**。
3. **只服务图片**：`.txt` / `.exe` / `.json` 一律拒绝。
4. **路由独立**：全部挂在 `/wechat-ui` 前缀下，不碰 DSH 任何既有路径。
5. **异常不外溢**：路由里所有错误都转成 HTTP 状态码，不让异常冒泡到宿主进程。
6. **前端有错误边界**：某条消息渲染炸了只降级那一条，不会白屏。

## 依赖与限制

### 依赖

| 用途 | 需要什么 |
|---|---|
| 界面（气泡 / 表情 / 设置面板） | **无外部依赖** —— `lib/` 是纯 ESM JavaScript，只用 Node 内置模块 |
| 桌面通知 / 确认窗 / 截图 / 热键 | Windows PowerShell（脚本随包附带在 `scripts/`） |
| 表情图片 | 一个存放图片的目录，用 `DSH_WECHAT_STICKERS` 指定 |

### 限制

- **桌面相关功能只支持 Windows**。气泡、折叠思考、设置面板这些界面部分跨平台可用。
- **只接管 `user` / `assistant-step` 两个渲染节点**。如果官方改了渲染器
  priority 规则，本插件可能被盖过 —— 此时控制台会有 `[wechat-ui]` 开头的报错，
  卸载插件即可恢复原样。
- **全局热键同机只有一个实例能抢到**（详见下面「已知副作用」）。
- **表情面板依赖 DSH 输入框的 DOM 结构**。官方换结构后会退化成
  「复制到剪贴板 + 弹提示」，功能不丢但要多一步手动粘贴。
- **运行时不做任何外部网络请求**。唯一的 HTTP 服务是挂在 `/wechat-ui`
  前缀下的只读图片路由。

## 已知副作用

- **热键互抢**：`Ctrl+Alt+Q` 是全局热键。同机同时跑两个 DSH 实例时，
  只有一个实例能抢到。插件会自动重试（45 秒一次，最多 40 次），
  先抢到的那边可用，日志里会看到：
  `热键监听退出了：code=2（多半被同机另一个 DSH 实例占了）`。
- **桌面确认弹窗**：多实例场景下两边都会弹。

## 排错

**右下角没有浮动按钮**
→ 刷新页面；还不行就重启 DSH。

**表情面板是空的 / 头像还是默认字**
→ 宿主半没加载。测 `/wechat-ui/stickers`，404 就重启 DSH。
→ 或者表情包目录不存在：检查 `DSH_WECHAT_STICKERS` 指向的目录是否有图片。

**点了表情但输入框里没出现标记**
→ 前端找不到 DSH 的输入框（它换了 DOM 结构）。会退化成
「复制到剪贴板 + 弹提示」，手动粘贴 `[表情:xxx]` 也行。

**界面整个变回原样了**
→ 渲染器可能被官方的 priority 规则盖过（官方哪天改了 priority）。
控制台会有 `[wechat-ui]` 开头的报错。先卸载插件即可恢复。
